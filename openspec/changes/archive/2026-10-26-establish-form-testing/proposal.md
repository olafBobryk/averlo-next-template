# Proposal

## Why

Form behavior currently lives in workflow prose without consistent end-to-end evidence. A shared behavioral specification and browser verification should cover complete forms and travel with independently generated projects.

## What Changes

- Initialize the standard OpenSpec Codex integration and spec-driven schema.
- Define a generic form-behavior capability, align login and support, and add a clearly labeled synthetic public contact demo.
- Verify actual forms, request boundaries, accessible feedback, retry, pending state and duplicate protection.
- Propagate applicable specs and verification through positive profile assembly.
- Link migrated workflow behavior to its specification; defer custom routing and schemas.

## Capabilities

### New Capabilities

- `form-behavior`: Accessible, server-validated form submissions with pending, recovery and explicit success behavior.

### Modified Capabilities

None.

## Impact

Login server action and client form, support client/server feedback, contact route and fixture endpoint, browser verifier, documentation, and profile assembly. No external delivery, deployment, new rate-limit threshold, or universal form framework.
